# 디자인 시스템 (2026-07-28 개편)

배경: [`requirements/3m-log 요구사항_20260728.md`](../requirements/3m-log%20요구사항_20260728.md) 5번 — 모바일 퍼스트 + "미니멀 + 터미널 GUI 긱(geek) 감성". 다크 테마 기조는 유지.

**컨셉 한 줄**: 개발 로그를 터미널에서 `cat`한 로그 파일처럼 보여준다. 카드+그림자의 일반적인 SaaS UI 대신, 하나의 터미널 세션 트랜스크립트로 피드를 구성한다.

이 문서는 실제 퍼블리싱(마크업/스타일링) 작업의 기준 문서다. `v1/view`에서 UI를 만들거나 고칠 땐 이 문서의 토큰과 컴포넌트 가이드를 따른다.

## 1. 컬러 토큰

| 이름 | Hex | CSS 변수 | 용도 |
|---|---|---|---|
| ink | `#0A0C0E` | `--color-ink` | 배경 |
| panel | `#131619` | `--color-panel` | 카드/모달 등 raised 표면 |
| line | `#23282C` | `--color-line` | 헤어라인 보더 (그림자 대신 이걸로 구분) |
| text | `#DCE1E6` | `--color-text` | 본문 |
| dim | `#616B75` | `--color-dim` | 타임스탬프, placeholder, 보조 텍스트 |
| signal | `#5FE3B3` | `--color-signal` | 프롬프트 문자, 링크, 포커스 링, 활성 태그 — 유일한 브랜드 액센트 |
| danger | `#D97757` | `--color-danger` | 삭제 등 파괴적 동작 전용. signal과 혼동되지 않도록 별도 색 유지 |

- `signal`은 "선택/활성/포커스" 전용, `danger`는 "삭제/에러" 전용으로 역할을 엄격히 분리한다 (섞어 쓰지 않음).
- 그라디언트, 다색 배지, 컬러풀한 태그 칩 금지 — 액센트는 signal 하나로 제한한다.

## 2. 타이포그래피

**폰트 하나로 통일**: [JetBrains Mono](https://fonts.google.com/specimen/JetBrains+Mono) (`next/font/google`). 페어링하지 않고 굵기/스타일만으로 위계를 만든다 — "미니멀"이라는 요구에 맞춘 절제.

| 역할 | 크기 (mobile / desktop) | 굵기 | 스타일 | 용도 |
|---|---|---|---|---|
| display | 20px / 24px | 700 | normal | 페이지 타이틀 |
| label | 13px / 13px | 700 | normal | 필드 라벨(`learned>`, `bug>`, `next>`), 버튼 |
| body | 14px / 15px | 400 | normal | 로그 본문, 폼 입력 |
| meta | 12px / 13px | 400 | italic | 날짜, 타임스탬프, placeholder |
| prompt | 14px / 14px | 500 | normal | 검색창, 로그인 프롬프트 |

- 모바일 기준 최소 폰트는 12px (monospace는 동일 px에서도 작게 느껴지므로 본문은 14px를 하한으로 둔다).
- `letter-spacing`은 label 역할에 한해 `0.02em` 정도로 살짝 벌려 라벨감을 강조한다.

## 3. 스페이싱 · 사이즈 규칙

- **모서리**: `border-radius`는 0~2px만 사용 (터미널은 각짐). 기존의 `rounded-xl`, `rounded-full` 계열 금지. 예외: 타이틀바의 트래픽라이트 점은 실제 OS 창 컨트롤을 그대로 참조하는 요소라 `rounded-full` 유지.
- **구분선**: `box-shadow` 대신 `1px solid var(--color-line)` 헤어라인 보더로 표면을 구분한다.
- **터치 타겟**: 버튼/태그칩/메뉴 등 인터랙티브 요소는 최소 44×44px.
- **간격 기준 단위**: 4px 배수 (Tailwind 기본 스케일 그대로 사용, 임의 값 지양).
- **가로 스크롤 금지**: 모바일 뷰포트 기준 어떤 요소도 뷰포트 폭을 넘지 않는다.

## 4. 레이아웃 컨셉

- **터미널 창 크롬**: 최상단에 얇은 타이틀바 (`3m-devlog — zsh`). 트래픽라이트 점 3개는 `sm:` 이상에서만 노출(모바일에선 공간 절약을 위해 생략).
- **검색 = 프롬프트**: 검색창을 `you@3mlog:~$ _` 형태의 프롬프트 라인으로 스타일링. 포커스 시 signal 색 커서 블록.
- **태그 = 인라인 grep 필터**: `#react` `#nest` 형태, 각진 보더, 활성 시 signal 색 텍스트+보더.
- **피드 = 로그 트랜스크립트**: 각 기록을 `$ devlog cat 2026-07-27.log` 형태의 커맨드 라인 + 아래 필드 출력으로 구성. 카드 사이는 그림자 대신 얇은 세로 가이드라인으로 연결해 하나의 세션처럼 보이게 한다.
- **버튼 = 브래킷**: 채워진 필(pill) 버튼 대신 `[ 새 로그 ]` 형태의 아웃라인 버튼, radius 최소.
- **로그인 = 부팅 프롬프트**: `$ 3m-devlog login` + 짧은 안내 한 줄, 버튼 2개(`[ Google 로그인 ]`, `[ Kakao 로그인 ]`).

## 6. 접근성 · 모션

- 키보드 포커스 링은 항상 `signal` 색으로 보이게 유지 (`outline`/`ring` 제거 금지).
- `prefers-reduced-motion` 존중 — 커서 블링크 등 장식적 애니메이션은 해당 설정에서 비활성화.
- 색만으로 상태를 구분하지 않는다 (예: 삭제 버튼은 색뿐 아니라 텍스트/아이콘으로도 구분).
- `:root`에 `color-scheme: dark`를 지정해 네이티브 폼 컨트롤(날짜 피커 아이콘/팝업 등)도 다크로 렌더링되게 한다. 이게 없으면 예: `input[type="date"]`의 캘린더 아이콘이 어두운 배경에 묻혀 거의 안 보인다.
