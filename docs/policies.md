# 정책 (Policies)

기능별로 확정된 비즈니스 규칙을 기록한다. 정책이 언제/왜 바뀌었는지의 변경 이력은 여기 남기지 않는다 — 그 역할은 `requirements/`와 `tasks/`가 한다. 이 문서는 항상 **현재 확정된 상태만** 반영한다.

## 인증 / 계정

- 로그인은 소셜 로그인(구글, 카카오)만 지원한다. 아이디/비밀번호 가입은 없다.
- 비로그인 사용자(게스트)도 메인 화면 열람과 로그 작성이 가능하다. 게스트 로그는 서버로 전송하지 않고 브라우저 localStorage에만 저장한다.
- 게스트 상태에서 소셜 로그인으로 전환해도, 로컬에 저장된 게스트 기록은 계정으로 이관되지 않는다.
- 회원탈퇴 시 계정과 해당 계정으로 작성된 모든 DevLog를 영구 삭제한다. 삭제된 데이터는 복구할 수 없다.

## DevLog (기록)

- 본인이 작성한 로그만 조회/수정/삭제할 수 있다. 다른 사용자의 글을 보는 소셜 피드 기능은 없다.
- `learnedNote`(배운 점)는 필수 입력, `troubleshootingNote`(버그), `tomorrowTask`(내일 할 일)는 선택 입력이다.
- 로그 작성/수정 시 기록 날짜를 선택할 수 있다. 기본값은 오늘 날짜이며, 선택 가능 범위는 오늘부터 과거 최대 1개월까지다. 미래 날짜는 선택할 수 없다.
- 검색은 `learnedNote`/`troubleshootingNote`/`tomorrowTask` 세 필드 모두를 대상으로 한다.

## 태그

- 태그는 대소문자 무관하게 동일한 태그로 취급한다(정규화 저장). 화면에 보이는 표기(`displayName`)는 최초 입력값을 유지한다.
- 로그 하나에 등록할 수 있는 태그는 최대 5개다.
- 인기 태그는 전체 사용자가 아닌 본인이 작성한 로그 기준으로 집계한다.
- 메인 화면 태그 칩은 참조(사용) 빈도가 높은 순으로 정렬하며, 최대 2줄까지만 노출하고 나머지는 숨긴다.

## 목록 조회 / 연속 기록

- 연속 기록(스트릭) 배지: 로그인 사용자에게만 적용한다(게스트 제외). 로그의 "기록 날짜"(`logDate`) 기준으로 연속 여부를 판단하며, 숫자 대신 아이콘 단계로 표현한다. 오늘 아직 기록이 없어도 어제까지 연속이었다면 단계는 유지되고, 연속이 끊기면 씨앗 단계부터 다시 시작한다. 헤더 근처에 노출한다.
  - 단계 전환 기준(연속 일수): 1일 이상 🌱(씨앗), 3일 이상 🌿(새싹), 7일 이상 🪴(화분), 14일 이상 🌳(나무).
- 목록 무한 스크롤: 로그인 사용자의 기록 목록에만 적용한다. 게스트 모드는 기존과 동일하게 전체 목록을 한 번에 보여준다.
- 날짜 기간 필터: "최근 7일 / 최근 30일 / 전체" 중 선택하며 기본값은 "전체"다. 기존 태그 필터·키워드 검색과 함께 교집합으로 적용되며, 로그인/게스트 모드 모두에 적용한다.

## AI 인사이트

- 로그인 사용자만 대상이다. 게스트 모드에는 인사이트 진입점 자체가 화면에 노출되지 않는다(게스트는 서버에 `ownerId`가 없어 애초에 대상이 아님).
- 기간 단위는 두 가지: 주간(ISO 8601 주차, 예 `2026-W31`)과 월간(캘린더월, 예 `2026-08`).
- 과거 기간은 제한 없이 선택해 생성 요청할 수 있다. 오늘이 속한 주/월보다 미래인 기간은 선택할 수 없다(프론트에서 다음 이동 버튼 비활성화, 서버도 요청 시 재검증).
- 기간당 결과는 최신 1건만 유지한다. 같은 `(사용자, 기간 종류, 기간)`으로 다시 생성 요청하면 이전 결과를 덮어쓰며, 과거 이력은 보관하지 않는다.
- 해당 기간에 로그가 0건이면 AI를 호출하지 않고 "기록이 없다"는 안내만 보여준다(불필요한 LLM 호출/저장 방지).
- 사용자에게 보이는 로그 수(`logCount`)는 항상 서버가 직접 센 값이며, AI가 생성하지 않는다.
