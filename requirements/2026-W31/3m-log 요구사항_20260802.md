📋 [기획서] 3분 개발 로그 서비스 (3-Min DevLog) — 6차 요구사항 업데이트

이 문서는 [3m-log 요구사항_20260801.md](./3m-log%20요구사항_20260801.md)에서 정의한 요구사항 위에 추가/변경되는 요구사항을 정리한다.

## 1. 인사이트 생성 진입점 UI/위치 변경

- 문제: 5차 요구사항에서 정의한 "헤더의 인사이트 진입점"이 실제 사용 화면에서는 눈에 띄지 않아, 사용자가 해당 기능의 존재 자체를 인지하기 어렵다.
  - 좌측 상단 헤더 영역에 다른 버튼들이 이미 여러 개 몰려있어, 진입점이 그 사이에 묻힌다.
- 요구사항:
  - 인사이트 진입점을 사용자가 쉽게 인지할 수 있는 위치/형태로 변경한다.
  - 다른 버튼들이 밀집한 좌측 상단 헤더 영역은 피한다.
  - 아이콘만으로 기능이 유추되지 않으므로, 이 진입점만은 텍스트(레이블)를 함께 노출하거나 별도로 구분되는 위치에 배치하여 "인사이트 기능이 있다"는 것 자체가 바로 인지되도록 한다.
  - 게스트(비로그인) 모드에는 노출하지 않는다는 기존 조건은 유지한다.

## 2. 인사이트 결과 저장/재사용

- 문제: 5차 요구사항에서 "생성된 인사이트는 서버에 저장되어 다시 확인할 수 있다"고 정의했으나, 실제로는 모달에서 인사이트를 생성해도 저장되지 않는 결함이 있다. 그 결과 같은 기간에 대한 인사이트를 볼 때마다 매번 다시 생성해야 하는 상황이다.
- 요구사항:
  - 인사이트 생성 결과는 반드시 서버에 저장되어야 한다 (5차 요구사항의 저장 조건이 실제로 동작하도록 하는 결함 수정).
  - 사용자가 인사이트 모달을 열었을 때, 조회하려는 기간(주간/월간)에 대해 이미 생성된 결과가 있으면 재생성 없이 저장된 결과를 바로 보여준다.
  - 새로 생성(재생성)은 사용자가 명시적으로 요청한 경우에만 수행하며, 이때 기존 결과를 덮어쓴다는 5차 요구사항의 동작은 그대로 유지한다.
